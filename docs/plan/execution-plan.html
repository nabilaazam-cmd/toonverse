    Toonverse Execution Plan

    Every task needed to build Toonverse, in the order to do them. Start at Task 001, finish it, check its “Done when” list, commit when a commit box appears, then go to the next number. The architecture and the 17 roadmap phases are unchanged; tasks keep a phase ID (3.4) and get a global number (046).

    Click a task’s status box to move it from [ ] Not started to [~] In progress to [x] Completed. The authoritative copies live in the repository under docs/: docs/architecture.html, docs/roadmap.html, docs/decisions.md, docs/plan/ and docs/git-workflow/. Decisions D1–D15 were confirmed by the team on 2026-10-12 (the D7 price is still pending).

    !Architecture issues / decisions required

    Breaking the phases into file-level tasks exposed these gaps. None changes the architecture. Each one says what the plan assumes and which tasks change if the team decides differently.

    I1Panels can only be rendered in the browser

    D2 stores published panels as PNGs in Cloudinary, and D3 keeps rendering in the browser. Konva runs only in the browser, so the backend can’t render panels itself. The plan has the browser render each panel and upload it through a new endpoint, POST /api/panels/:panelId/render, inside the existing Publishing module.

    Tasks {10.1}, {10.2}, {10.5}

    I2Nowhere to count daily AI use

    The AI quota (D11) needs a per-user daily counter, but the data model has none. The plan adds an aiUsage { date, count } field to User instead of a new collection. This needs team approval.

    Tasks {2.2}, {5.10}

    I3Cookie auth needs the frontend and API on one site

    A SameSite=Lax cookie (D4) is not sent with cross-site requests. In production the frontend and API must share a site (for example toonverse.app and api.toonverse.app). Otherwise the cookie must become SameSite=None; Secure, which needs extra CSRF care. Decide with hosting.

    Tasks {3.3}, {15.1}, {15.6}

    I4The JazzCash return doesn’t carry the session

    JazzCash sends the browser back with a cross-site POST, so the Lax cookie isn’t sent. The return handler finds the payment by pp_TxnRefNo and trusts only the verified hash, never the session.

    Task {11.14}

    I5HD export can’t be enforced on the server

    Export resolution is a premium limit (D6), but export runs in the browser (D3), so a determined user could bypass it. Layer and AI limits are enforced on the server. The team confirmed (Q2) that this is documented as a known limitation and never described as server-enforced security.

    Tasks {9.6}, {16.6}

    I6Guest Mode has no backend part

    D1 makes Guest Mode client-only, so the backend Authentication module does nothing for guests. Guests use Discover, Reader view and an unsaved canvas sandbox.

    Tasks {3.27}, {6.22}

    I7Node.js 20.6 or newer is required

    The plan uses Node’s built-in --env-file and --watch instead of adding dotenv and nodemon.

    Task {1.2}

    I8Episode reordering collides with the unique index

    The unique { series, number } index breaks a simple renumbering, so reorder runs in two passes.

    Task {4.8}

    I9Discover has no cover images

    The architecture defines no series cover, so Discover cards are text only. Using a series’ first published panel as its thumbnail would be a new decision.

    Task {10.9}

    I10Decisions D1–D15 are confirmed

    The team confirmed D1–D15 on 2026-10-12; tasks 0.2–0.5 now review and commit the prepared decision log. Vite and Mongoose are confirmed; the remaining supporting libraries in roadmap section 02 still need the team’s approval in task 0.5.

    Tasks {0.2}–{0.5}

    I12The premium price is not decided

    D7 fixes a one-time sandbox payment for 30 days, but the PKR amount is pending. No task may invent a price: task 11.1 asks the team before any payment code uses it.

    Tasks {0.4}, {11.1}, {11.13}

    I13Local recovery is required scope (D10)

    Option A adds a browser recovery draft to manual save and auto-save. Former backlog task 8.16 moved into Phase 8 as a P0 task, and one new task (8.17) offers restore or discard, because choosing between an old draft and a newer server version is its own screen with its own rules. Drafts are stored per user in IndexedDB so members sharing the laptop never see each other’s drafts.

    Tasks {8.6}, {8.16}, {8.17}, {8.14}

    I11An admin audit trail would add a collection

    The optional audit trail (P3) needs an AdminAction collection. It stays in the backlog until the team approves it.

    Task {12.14}

    AToonverse development phases

    The 17 roadmap phases, unchanged. For one continuous order, two phases are split. The canvas spike (6.1–6.3) runs right after setup because it decides the Panel model. AI assistance (5.6–5.18) runs after the MVP, so the MVP never waits for OpenAI. The optional backlog comes last.
